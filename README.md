# Safe Home MVP (규칙 기반 + 문장 해석만 Gemini)

충북대 근처 자취방을 추천하고, 계약 전에 위험 신호를 점검하는 시연용 MVP예요.
노션의 **MVP 설계 (초안)**, **11/10 설문 가중치**, **11/11 회의 제안(예시 계약서 불러오기)**, **11/12 회의 결정(Gemini 연결 방식)**을 바탕으로 만들었어요.

> 매물·계약서·등기는 **가상 샘플 데이터**이고, **시세만 국토교통부 전월세 실거래가(실제 공공데이터)**예요. 실제 개인정보는 없어요.

## AI(Gemini) 연결 — 11/12 회의 결정

```
현재:  사용자 문장 → [🤖 AI로 조건 분석] → /api/parse (Vercel 서버리스 함수) → Gemini → 조건 JSON
                                                                         ↓ 실패하면 규칙 해석으로 대신
       입력칸 확인·수정 → [🔎 매물 검색] → SQLite 데이터 검색 → 설문 가중치 점수 → 결과   (Gemini 0회)
```

- **버튼 분리**: 「AI로 조건 분석」은 Gemini를 1번 불러 입력칸만 채워요. 「매물 검색」은 지금 입력칸 값으로만 검색하고 AI를 부르지 않아요.
- **키 위치**: Gemini 키는 브라우저 코드에 없고, Vercel 서버리스 함수(`api/parse.js`)의 환경 변수에만 있어요.
- **AI 역할은 문장 해석뿐**: 검색·점수·시세 비교·계약 점검은 모두 규칙이에요. AI 답도 허용된 값(정문/중문/후문, 원룸/투룸/오피스텔, 옵션 6종 등)과 숫자 범위만 받아요.
- **실패하면 규칙으로**: 키가 없거나, 한도 초과, 응답 지연(15초), 오류가 나면 안내 문구를 띄우고 규칙 해석으로 채워요. 시연이 멈추지 않아요.

### 키 등록 (팀원이 한 번)

1. [Google AI Studio](https://aistudio.google.com/)에서 API 키 발급 (키는 채팅·노션·GitHub에 붙여 넣지 않아요)
2. Vercel 프로젝트 → **Settings → Environment Variables** → `GEMINI_API_KEY` 추가 (Production·Preview 체크)
3. **Deployments**에서 최신 배포를 **Redeploy** (환경 변수는 다시 배포해야 반영돼요)

### 호출 횟수 제한

| 위치 | 기본값 | 바꾸는 법 |
| --- | --- | --- |
| 입력 길이 | 200자 | `api/parse.js`의 `MAX_CHARS` |
| 한 사용자(IP) 분당 | 5번 | 환경 변수 `LIMIT_PER_MINUTE` |
| 한 사용자(IP) 하루 | 30번 | 환경 변수 `LIMIT_PER_DAY_IP` |
| 서비스 전체 하루 | 200번 | 환경 변수 `LIMIT_PER_DAY_TOTAL` |
| 화면 한 번 접속당 | 10번 | `ai_parse.py`의 `SESSION_LIMIT` |

### 화면의 「검색 제한」 칸 (Gemini 사용량)

① 집 찾기 화면 검색창 아래에 Gemini(AI) 사용량을 막대로 보여 줘요. 한도를 넘으면 AI 대신 간단 해석으로 찾아요(검색은 계속 돼요).

| 항목 | 기준 |
| --- | --- |
| 이 화면에서 남은 AI 사용 | 접속당 10번 |
| 나의 오늘 · 최근 1분 | IP 기준 하루 30번 · 분당 3번 |
| 사이트 전체 오늘 | 하루 450번 (Google RPD 500) |
| 사이트 전체 최근 1분 | 분당 12번 (RPM 15) · 토큰 20만 (TPM 25만) |

- AI로 찾을 때마다 서버 응답의 숫자로 바뀌고, 「새로고침」은 `GET /api/parse`로 숫자만 다시 불러와요(Gemini는 부르지 않음).
- 한도에 걸려 간단 해석으로 찾았으면 ② 추천 결과에 "검색 제한 · 이유"가 나와요.
- Google이 429를 주면 1분 쉬고, 그동안 "○초 뒤에 AI를 다시 써요"가 보여요.
- 서버 숫자는 함수 메모리 기준이라 대략이에요. 서버가 새로 뜨면 0부터 다시 세요.

- 모델은 `gemini-3.5-flash-lite`예요 (`gemini-2.5-flash`는 새 계정에서 404). 바꾸려면 환경 변수 `GEMINI_MODEL`.
- 무료 등급 한도(11/12 AI Studio 확인): **RPM 15 · TPM 25만 · RPD 500**. 전체 하루 200번이 RPD보다 작아서 그대로 둬요. 한도가 바뀌면 AI Studio → **Dashboard → Rate Limit**에서 다시 확인하고 `LIMIT_PER_DAY_TOTAL`을 **RPD보다 작게** 잡아 주세요.
- 동시에 여러 명이 누르면 분당 15번(RPM)에 먼저 걸릴 수 있어요. 그때는 Gemini가 429를 주고 화면은 규칙 해석으로 대신해요.
- 서버 쪽 제한은 함수 메모리에 저장하는 최소한의 방어예요. Vercel이 함수를 새로 띄우면 숫자가 초기화될 수 있어요. 마지막 안전장치는 Google 할당량이고, 넘으면 규칙 해석으로 대신해요.

## 실거래 시세 갱신

```bash
python fetch_market.py   # 인증키를 물어봐요(화면에 안 보임). 키는 저장되지 않아요
```

- 청주시 서원구(개신·사창·성화·모충동) 단독·다가구와 오피스텔 월세 거래 최근 12개월을 받아 `market_prices.csv`(동·유형별 환산 월세 중위값)를 만들어요.
- 원룸 30㎡ 미만, 투룸 30~50㎡로 면적 기준 구분. 거래 3건 미만인 동은 서원구 전체(동별 중위값 가중 평균)로 비교해요.
- 가상 매물 100건의 가격은 이 실제 중위값을 기준으로 만들어요(약 70% 비슷, 15% 싸게, 15% 비싸게). `python db_seed.py`로 다시 만들 수 있어요.

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py        # safehome.db가 없으면 자동으로 만들어요
python test_mvp.py          # 규칙 검증 테스트 (Gemini는 흉내만 내서 키 없이 돌아가요)
python db_seed.py           # DB를 처음부터 다시 만들 때
```

로컬에서 AI 분석까지 쓰려면 `SAFEHOME_API_URL=https://(배포 주소)/api/parse`를 환경 변수로 주고 실행해요. 없으면 규칙 해석만 써요.

## 화면 3단계 (버튼을 누르면 다음 단계로 넘어가요)

| 단계 | 하는 일 |
| --- | --- |
| 1 집 찾기 | 문장을 쓰고 「찾기」 → Gemini로 조건 해석(실패 시 규칙) → 바로 검색해서 **2단계로 자동 이동**. 「조건 직접 고르기」에서 입력칸으로만 찾을 수도 있어요(Gemini 0회) |
| 2 추천 결과 | 검색 조건 태그, 필수 조건 필터, 설문 가중치 정렬, 한 달 비용, 실거래 시세 대비, 계약 위험 배지 → 「계약서 점검하기」를 누르면 **3단계로 자동 이동** |
| 3 계약 점검 | 가상 계약서·등기부를 문서 모양으로 보여 주고 **위험·주의 줄에 색과 번호** 표시 → 번호별 설명·물어볼 것 → 문자 초안. 내용은 직접 고칠 수 있어요 |

## 파일 구조

| 파일 | 내용 |
| --- | --- |
| `app.py` | Streamlit 화면 |
| `recommend.py` | 문장 해석(정규식), AI 답 검사(`cond_from_ai`), 필터, 설문 가중치·ROC 혼합, 점수, 시세 비교 |
| `ai_parse.py` | 브라우저에서 `/api/parse` 부르기, 실패 시 안내 |
| `api/parse.js` | Vercel 서버리스 함수: Gemini 호출, 입력 길이·횟수 제한, 오류 처리 (키는 환경 변수) |
| `contract_check.py` | 텍스트 계약서·등기 읽기, 8개 항목 규칙, 특약 키워드 분류, 질문·문자 초안 |
| `db_seed.py` | SQLite DB 생성 (매물 100건, 계약 사례 10종) |
| `fetch_market.py` | 국토부 실거래가 수집 → `market_prices.csv` |
| `market_prices.csv` | 동·유형별 실거래 시세 중위값 (키 없음) |
| `test_mvp.py` | 사례별 기대 판정·가중치·필터 테스트 |

## DB 구조 (`safehome.db`)

- `listings` — 가상 매물 (보증금, 월세, 관리비, 넓이, 채광·조용함 1~5, 옵션, 정문·중문·후문 도보 시간, 사례 ID)
- `contracts` — 매물별 **계약서 원문 텍스트** (`contract_text`)
- `registries` — 매물별 **등기 요약 원문 텍스트** (`registry_text`)
- `cases` — 사례 10종과 기대 판정 (검증표)
- `market_prices` — 동·유형별 시세 (`market_prices.csv`의 실거래 중위값)

## 계약 점검 규칙

모든 항목은 **정상 / 주의 / 위험 / 확인 필요** 중 하나예요. 문서에 값이 없으면 추측하지 않고 **확인 필요**로 보내요.
종합 판정은 가장 나쁜 항목을 따르고, 확인 필요가 남아 있으면 "양호"라고 하지 않아요.

| 항목 | 기준 |
| --- | --- |
| 임대인·소유자 일치 | 불일치 🔴, 위임장 있는 대리인 🟡, 신탁회사 소유 🔴 |
| 보증금 회수 위험 비율 | (근저당 채권최고액 + 선순위 보증금 + 내 보증금) ÷ 시세 — 70% 🟡, 80% 🔴 |
| 압류·가압류 | 있으면 🔴 |
| 신탁 등기 | 있으면 🔴 |
| 임차권등기 | 있으면 🟡 |
| 최근 소유권 이전 | 계약 작성일 기준 90일 이내 🟡 |
| 납세증명서 | 미확인 🟡 |
| 특약 | 전입신고 제한·보증금 반환 지연·담보 추가 허용 🔴 / 수리비 전가·과도한 원상복구·중도 해지 위약금 🟡 |

## 3D 방 둘러보기 (11/13 추가)

- 「3 계약 점검」 화면 위쪽에 **🧊 3D로 방 둘러보기**가 있어요. 드래그로 돌리고, 휠·두 손가락으로 확대해요.
- 모델은 휴대폰 3D 스캔 앱 **KIRI Engine**으로 실제 집을 찍어 GLB로 내보낸 파일이에요 (`assets/room_scan.glb`, 5.6MB). 원본(172MB, 약 200만 면)을 휴대폰에서도 열리게 약 25만 면·2048px 텍스처(WebP)로 줄였고, 스캔에 찍힌 사람은 모자이크 처리했어요. 가상 매물과 같은 방은 아니고 기능 시연용이에요.
- 3D 표시는 Google의 `<model-viewer>`(BSD-3)를 `assets/model-viewer.min.js`로 같이 올려서 써요. 외부 CDN이 막혀도 동작해요.
- 다른 방으로 바꾸려면 새 GLB 파일을 `assets/room_scan.glb` 이름으로 덮어쓰면 돼요.
